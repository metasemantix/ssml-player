# SSML Player

An Android 10+ app for importing or pasting a bounded SSML lesson, rendering it with an installed **offline** Android TextToSpeech voice, and listening with play/pause/stop and a media notification. No accounts, analytics, server, or Internet permission. Version 0.1.0 is an initial vertical slice, not a complete SSML implementation.

## Build and install

Use JDK **21**, Android SDK platform **35**, and build-tools **35.0.0**. Set `ANDROID_HOME` to your SDK, or use Android Studio's ignored `local.properties`. The committed Gradle wrapper downloads and verifies Gradle **8.11.1**. The compatible baseline is AGP **8.9.2**, Kotlin/Compose compiler **2.1.20**, Compose BOM **2025.04.01**, and Media3 **1.6.1**. JVM bytecode targets Java 17; minimum Android SDK is 29 and target SDK is 35.

```sh
./gradlew :core:test :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The `Android debug APK` GitHub Actions workflow runs those checks for pull requests and main, and can be started manually. Download `ssml-player-debug` from a successful run's artifacts, unzip, and install `app-debug.apk` on Android 10 or later. Android may require allowing installation from your file manager. This is a development-signed APK, not a production release. CI artifact availability depends on an actual successful workflow run.

## Listen

1. Install an Android TTS engine and its offline voice data through Android settings. Voice downloads may require a connection in the engine/settings app; SSML Player itself has no network permission.
2. Open SSML Player, choose an engine and an offline voice. Use **TTS settings**, then **Reload engines** after installing voice data. Android may fall back to its default engine if a requested engine cannot initialize; check the reported voices.
3. Use the built-in sample, paste/edit SSML, or **Import SSML** with the system document picker. Imported files must be UTF-8. The picker supports arbitrary file extensions; parsing determines whether the contents are supported SSML. A cloud document provider may download a file outside this app; use local storage for a fully offline workflow.
4. Tap **Render locally**, keeping the screen/app open until rendering completes. Then tap **Play**. Pause/resume and stop are available in the app; Android media controls support background/lock-screen playback. Stop returns to the beginning; Cancel aborts rendering. Editing the document or changing voice invalidates the old audio.

## Behavior and limits

- Supported tags: `speak`, `p`, `s`, `break time`, nested `prosody rate/pitch`. See [the exact support matrix](docs/ssml-support.md). Unsupported tags, attributes, namespaces, and malformed XML cause a visible error. IPA/phoneme and say-as are explicitly unsupported.
- DTDs, external entities, and processing instructions are rejected. Input is limited to 128 Ki UTF-16 characters, 32 levels, and 512 audio segments. Speech chunks contain at most 2,000 characters without splitting surrogate pairs.
- Each speech chunk is synthesized to an app-private temporary file through a replaceable backend. No direct TTS `speak()` queue is used. Accepted engine output is RIFF/WAVE PCM16, mono/stereo, 8–48 kHz. Unsupported/truncated output produces an error. Synthesis and initialization have 60-second and 15-second coroutine deadlines, including submission/setup. A blocking Android Binder call cannot be forcibly interrupted: timeout/cancellation cleanup waits for that call and `stop`/`shutdown` to return, off the UI thread.
- Each break is inserted as zero-valued PCM frames into one streamed lesson WAV at the speech voice’s sample rate/channel count, rounded to the nearest whole frame per break. Each break is 0–10 seconds; total explicit silence is at most 120 seconds. Media3 plays **one local media item**, removing avoidable item transitions and speech/silence sample-rate changes. All speech chunks must have the same PCM format; a change produces a visible error. No resampling, crossfade, or silence trimming is applied. Engine-provided leading/trailing silence is preserved, so audible pauses may still exceed the explicit break; exact device output timing is unverified.
- Prosody is an approximation: nested multipliers are applied through Android rate/pitch controls. Engines may ignore or approximate them even when the API reports success. Only voices that report no network requirement and no missing-data flag are offered. Incorrect engine metadata/behavior cannot be independently verified by the app; test your voice in airplane mode.
- Audio assembly streams in 8 KiB buffers on IO workers. Each engine output file is capped at 32 MiB after synthesis; the assembled lesson (header, speech and inserted silence) is capped at 128 MiB before each append. Each temporary speech file is deleted after appending it. Peak normal cache use can include the lesson plus one 32 MiB speech file; an in-progress engine write is checked only after completion. Each render and service instance owns a separate directory. Cancellation joins prior work and requests engine stop before deleting partial output or starting replacement work; abandoned directories from process death are scavenged on the next service initialization without deleting another live instance’s directory. Stop retains a completed lesson for replay. Android may evict cache files.
- Cancel immediately updates the UI to “Stopping…”; rendering controls remain busy until the previous engine call and cleanup return. Slow or hung engine calls can therefore delay cancellation/engine replacement, while the app’s caller thread is free. Rendering is **not promised to survive backgrounding/process death**; keep the app open until ready. Playback uses a media foreground service, handles audio focus and unplugged headphones, and takes a wake lock during playback. Playback does not survive process death, a force-stop, or a reboot. Completed audio is not exported/persisted as a saved lesson. Removing the task while playing is intended to continue playback; removing it while paused stops the service.
- The foreground-service/media-playback permissions enable the media notification and background playback. `WAKE_LOCK` supports screen-off playback. There is no Internet, microphone, or broad storage permission; document access uses Android's picker. Android may apply manufacturer-specific battery restrictions.

## Architecture and verification

`:core` contains the strict parser, PCM metadata validator/streaming assembler, `SpeechEngine` interface, worker-dispatched `SpeechSession`, and `SerializedOperations` cancellation queue. Android uses the platform XML pull parser; JVM tests use kXML2. `AndroidTtsEngine` adapts Android TTS. Construction, catalog/voice queries, rate/pitch, synthesis submission/file opening, stop and shutdown are invoked on IO workers. `PlaybackService` keeps player/state work on Main and parsing/assembly/cache cleanup on IO; replacements join the prior job, including noncancellable engine cleanup. Service destruction queues cleanup off Main. The Compose activity binds locally. No SSML is sent to media controllers.

Automated checks cover valid/malformed XML, DTD/external/internal entities, unsupported markup, nested prosody scoping, resource limits, Unicode chunking, PCM silence bytes and corrupt WAV rejection. Fake-engine tests exercise worker dispatch, slow constructor/submission/stop, initialization cancellation/failure/timeout, late callbacks and interrupted synthesis. Queue tests enforce replacement/destruction cleanup ordering. Assembly tests compare exact PCM frames, leading/trailing/zero breaks, mono/stereo timing, metadata skipping, cancellation, size bounds and format-change rejection. A build and lint verify packaging and Android API usage. They cannot establish audible TTS correctness or device lifecycle behavior.

### Manual device checklist

- Install APK; install an offline voice; enable airplane mode. Load [samples/lesson.ssml](samples/lesson.ssml), render, and listen to the entire lesson.
- Compare the 1,500 ms break with the 1,000 ms break and a zero break between speech chunks. Record playback via the device/audio test setup and inspect its waveform around boundaries. Verify there are no item-transition dropouts, while distinguishing inserted zero frames from silence already supplied by the TTS engine. Check nested rate/pitch and at least two offline voices/engines; engine padding and output-device buffering are not covered by the JVM sample tests.
- Import a local `.ssml` file, then paste equivalent SSML. Try invalid UTF-8, malformed XML, a DTD, `<phoneme>`, `<say-as>`, unsupported attributes, oversized input, and excessive pauses. Confirm clear errors without playback of flattened text.
- Change engine/voice; try missing voice data and an engine with only online voices. With a slow offline voice (or a local test engine that delays init/synthesis/stop), cancel during setup and render, reload engines repeatedly, and destroy/recreate the activity/service. Confirm the UI keeps responding, “Stopping…” lasts until cleanup finishes, no stale lesson becomes playable, and the next render succeeds without cache collisions. Use Android Studio System Trace/CPU profiling to inspect Main versus IO/Binder threads. These tests require a physical device: Android’s own TTS ServiceConnection callbacks/internal locks and vendor Binder behavior are outside the fake-engine tests, so moving app call sites off Main does not guarantee an unresponsive engine can never stall platform code.
- During playback, pause/resume/stop, unplug headphones, receive another audio source/call, lock the screen, background the app, use notification/headset controls, rotate the activity, and remove the task. Check on Android 10 and a current Android version. Repeat with a longer lesson and inspect cache cleanup/storage bounds.
- Force-stop/relaunch; confirm the previous render is discarded and the app can render again. Do not expect process-death playback restoration.

Device listening/background checks have not been run in the cloud environment. See `codex_task.md` for actual build/test results and pending acceptance criteria.
